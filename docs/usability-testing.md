# Courtside usability testing

Use the sample-data demo to run the tasks below. Start Courtside with `npm run dev` and open [Fantasy impact with sample data](http://localhost:3000/?demo=1#fantasy). Ask the participant to think aloud and leave the walkthrough instructions collapsed. If they open the instructions, record which tasks they completed with help.

| Task to read to the participant | What to observe |
| --- | --- |
| A guard on your roster is out. Find Alex Morgan and tell me how many games Boston has in the next seven days. | Reaches the correct card and reports three games. |
| Find two teammates you might investigate as replacements for Alex. | Finds Jordan Reed and Casey Brooks through the replacement controls. |
| Compare the two teammates. Who has the higher seven-day baseline, and what would you check before making a roster move? | Identifies Jordan Reed, explains that the baseline assumes full participation, and names a further check such as role, minutes, or league availability. |

For each task, record the build or commit, device, elapsed time, completion without help, completion with help, or abandonment. Capture the action or wording that caused hesitation. Ask permission before quoting a participant and use an anonymous participant ID in public notes.

## Reporting results

For each task, report the number of unaided completions out of the number who attempted it. Pair each recurring issue with the observed behavior, the corresponding change, and the result of a follow-up session if available. Include the date, participant count, device mix, and recruiting criteria so readers can interpret the findings.
